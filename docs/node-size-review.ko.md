# 연결 수에 따른 노드 크기 검토

상태: 검토안. 이번 목록 UI 변경에서는 그래프의 크기 공식을 변경하지 않았다.

## 권고

전체 자료의 **고유 인접 자료 수**로 크기를 계산한다. 같은 두 자료 사이에 참조·근거 등 관계가 여러 개 있어도 한 번만 센다. 검색 결과나 주변 보기 범위가 바뀌어도 같은 자료는 같은 크기를 유지한다. 크기는 연결 정도를 뜻하며, 신뢰도나 업무 중요도를 보장하지 않는다.

기본 배율에서 반지름 `3 + min(5, 1.25 × ln(1 + 연결 수))`를 권한다. 직선적인 증가보다 허브의 과도한 확대를 줄일 수 있다.

| 연결 자료 수 | 권고 반지름 | 대략적인 지름 |
|---:|---:|---:|
| 0 | 3.0px | 6px |
| 1 | 3.9px | 8px |
| 5 | 5.2px | 10px |
| 10 | 6.0px | 12px |
| 30 | 7.3px | 15px |
| 100 | 8.0px | 16px |

현재 구현도 제곱근 증가를 적용하지만 기본 배율 반지름이 3.25~4.5px에 그쳐 차이가 작다. 권고안은 허브를 더 명확하게 보여준다.

## 적용 시 함께 바꿀 부분

- 시각 반지름, 충돌 회피 반경, 클릭 범위, 라벨 간격을 하나의 크기 계산에 맞춘다.
- 줌을 반영한 화면상 최대 크기를 별도로 제한한다. 위 수치는 기본 배율 기준이다.
- 이름의 글자 크기는 노드에 비례해 키우지 않는다. 선택·확대 시 이름을 점진적으로 표시한다.
- 자료 유형은 색상, 연결 정도는 크기, 선택 상태는 테두리로 구분한다.
- 실제 연결 분포와 허브가 많은 1,000개 자료에서 겹침·클릭·가독성을 다시 검수한다. 기존 균일한 데모의 연결 분포만으로 효과를 판단하지 않는다.


## 2026-10-14 구현 확인

현재 공식은 기본 배율에서 반지름 `3.2 + min(2.3, 0.5 × log2(1 + 고유 이웃 수))`이다. 위의 3~8px 제안은 채택하지 않고 기존 작은 노드를 보존했다. `buildAdjacency`의 Set으로 전체 자료 고유 이웃 수를 구하므로 여러 관계 유형·관계 필터·검색·300개 표시 제한이 노드의 크기 의미를 바꾸지 않는다. 범례에 이 의미를 표시했다.

새 밀집 표시 테스트는 1,000개 범위에서 표시량 제한, 선택 자료 보존, 추가 표시 가능성, 필터 밖 자료 미포함을 확인한다. 이는 시각적인 허브 배치·겹침 검수를 대신하지 않으며 브라우저 검수와 구분한다.
