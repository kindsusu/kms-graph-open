# 읽기 전용 운영 방향

사용자 결정: Cloudflare는 검색·목록·상세·그래프를 제공하는 읽기 전용 사이트다. 자료의 추가·수정은 Notion 또는 Google Sheets에서 한다. 사이트 내 작성·업로드 API와 D1/R2 데이터 저장소는 사용하지 않는다.

원본 편집 → Python 수집·승인 검증 → out 폴더 생성 → Cloudflare 정적 배포 순서다. 원본 변경이 방문자의 화면에 실시간 반영되지는 않으며 다시 빌드하고 배포해야 한다. 이번 작업은 자동 실행 일정이나 CI 자격 증명을 만들지 않는다.

기존 사이트/도메인/참조데이터 구조에 더해 독립 문서·도구, 관계 근거, 공용 폴더·프로젝트·소속을 CSV/Sheets/Notion의 선택적 입력으로 지원한다. [입력 예제와 Notion 설정](../sample/explicit-inputs/README.md)을 참고한다. 새 입력의 승인 체크가 없으면 공개하지 않으며 승인 관계·소속이 미승인 자료를 가리키면 빌드를 중단한다. 세부 원본 설정은 config.example.json을 복사해 로컬 config.json에 작성한다. 실제 계정 연결은 아직 검증하지 않았다. 샘플 `knowledge.json`은 `--knowledge`로 명시할 때만 병합되며 운영 config의 기본값은 비어 있다. 이 JSON은 관리자가 공개를 확정한 기존 입력으로 취급한다.

출처 ID·URL, 원본 수정일과 수집일을 구분해 표시한다. 명시 자료에는 변경되지 않는 ID를 부여한다. 신규 Notion 자료의 ID가 비어 있으면 페이지 ID에서 생성하지만 관계·소속에서 사용할 명시 ID를 권장한다. 기존 자료의 ID는 출처 정보를 추가해도 바뀌지 않는다. 이름에서 ID를 생성하던 기존 참조데이터를 이름 변경할 때는 기존 생성 ID를 명시 ID에 먼저 기록한다.

재검토 후보는 이전 게시 자료의 검증된 내부 스냅샷과 비교한 변경에 한정한다. `references/based_on` 의존 관계를 따라 영향 후보를 계산하며 첫 빌드에는 후보가 없다. 원본 재수집 시각과 URL 확인 결과만 바뀌면 후보를 만들지 않는다. 삭제된 원본 ID는 공개하지 않고 개수만 알린다. 후보는 지난 게시 대비 안내로 다음 무변경 빌드에서 사라지며, 검토 완료 상태를 저장하는 할 일 목록은 아니다. 자료를 자동 폐기하거나 승인 상태를 바꾸지 않는다. 공용 구조는 원본에서 수정하고 개인 폴더·프로젝트는 브라우저에서 따로 관리한다.

Cloudflare 배포 대상은 out 폴더다. config.json, 토큰, 서비스 계정 파일, .out-state의 내부 보고서는 배포하지 않는다. out에는 `index.html`, `assets/`, 선택 `.nojekyll`만 허용하며 다른 관리자 파일이 있으면 빌드는 삭제 없이 실패한다. 정적 HTML에 포함된 자료는 사이트에 접근하는 사람에게 제공되므로, 사내 자료의 사이트 접근 제어는 별도 호스팅 설정으로 관리한다.
